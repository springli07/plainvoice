# 设计与使用边界

PlainVoice 将可定位的文风偏好、生成过程中的概率控制和改写后的内容检查分开。这样可以知道一个结果用了什么机制，也能单独验证每一层是否工作。

## 系统分层

| 层 | 输入与输出 | 能验证什么 |
|---|---|---|
| 文风配置 | 可编辑短语与有界权重 | 配置是否合法、规则是否明确 |
| 离线诊断 | 原文 → 命中位置、指标与解释 | 命中确实对应原文，保护区没有被误计 |
| 生成适配 | 原文与偏好 → 模型候选文本 | 请求参数、超时、后端错误与输出格式 |
| 本地解码 | 已生成 token 与 logits → 调整后的 logits | 上下文匹配、权重边界、批次隔离 |
| 内容保留 | 原文与候选 → 通过或问题清单 | 数字、代码、引用等确定性约束 |
| 工作台与 CLI | 用户输入 → 诊断或受检改写 | 功能链路、错误呈现、无密钥时的行为 |

诊断结果不回答“谁写了这段文字”。一个文风偏好也不能证明某个词本身具有作者身份属性。

## 为什么不能简单按“人类词”加权

模型通常先给词表中的每个 token 一个 logit，再将这些值归一化为概率：

```text
调整后 logit(v) = 原 logit(v) + 有界偏置(v, 已生成上下文)
概率(v) = softmax(调整后 logits)[v]
```

给一个候选加 `1`，并不等于给它的概率加一个百分点。最终变化还取决于其他候选的分值。

词、短语和 token 不是同一种单位。把一个中文短语编码后逐个压低它包含的 token，会同时压低其他正常句子中的共享部分。偏置过强也可能逼模型绕用更拗口的近义词，或者改变原本需要表达的意思。

因此，默认策略是限制权重、减少重复短语的完成概率，并将正向偏好交给明确的配置或自有语料。它不要求文章刻意制造长短句差异，也不为提高某个分数强行替换正常词语。

## 短语级本地解码

假设某条短语实际编码为 `[a, b, c]`。当已生成文本以 `[a, b]` 结尾时，规则才调整候选 `c`。在其他上下文中，不会因为这条规则全局惩罚 `a`、`b` 或 `c`。

这不是对整个短语出现概率的精确约束：模型仍可使用其他切词、插入内容或转向近义表达。它也不能让模型理解“所有不自然的句式”。优点是行为清晰，能够写出上下文和词表边界测试。

计划必须与生成时的 tokenizer 保持一致。模型名称相近、词表大小相同，都不足以证明 tokenizer 相同。词表越界、空编码、特殊 token 和不匹配的 tokenizer 元数据应拒绝使用。

Hugging Face 集成通过 `PhraseLogitsProcessor` 实现。处理器只读取新增的生成 token，不把输入提示词当成已经生成的句子；每个批次序列独立计算。使用本地模型的依赖是可选项，导入基础包不会下载模型。

CLI 的 `rewrite --backend local --model <本地目录或缓存标识>` 只使用已有本地权重，使用该模型标识作为计划的 tokenizer 标识。目前适配器使用 CPU，要求模型带聊天模板，单次最多生成 1,024 个新 token。首次准备模型、确认模型许可和评估硬件容量是使用者的独立准备步骤。没有真实模型权重的环境，仅完成算法测试不能算作本地推理已经可用。

## 语料校准

训练时为参考语料和模型语料统计 token 频率，做平滑后计算两者的对数频率比。输出保留 tokenizer 标识、样本规模、训练参数与有界权重。

至少需要以下约束：

1. 过滤支持度不足的 token，避免少数样本主导权重。
2. 排除特殊 token 和不合适的空白候选。
3. 限制最大偏置；默认不启用正向增强。
4. 在未参与训练的文本中评估，并单独检查重复与事实保留。

训练语料应尽量匹配题材、事实约束、长度和写作任务。例如，用文学散文对比技术手册，学到的主要是体裁差异。`--human` 只是参考语料目录的接口名称，不是对其中材料作者身份的验证。

CLI 的 `fit --tokenizer` 使用 tiktoken 编码名称。若给 Hugging Face 本地模型训练偏好，应通过 Python 接口使用该模型自己的 tokenizer，并保持完全相同的标识：

```python
import json
from pathlib import Path

from transformers import AutoTokenizer
from plainvoice.corpus import fit_token_bias

model = "/path/to/cached-model"
tokenizer = AutoTokenizer.from_pretrained(model, local_files_only=True)
table = fit_token_bias(
    human_texts=["你有权使用的参考文本……"],
    model_texts=["同题材的模型文本……"],
    tokenizer=tokenizer,
    tokenizer_id=model,
    min_count=5,
)
with Path("local-token-bias.json").open("x", encoding="utf-8") as output:
    json.dump(table, output, ensure_ascii=False, indent=2)
```

这里的两段短文本仅展示接口，通常不足以训练有意义的表。实际使用应提供足量、分组一致的材料，再用 `rewrite --backend local --model <相同路径> --bias-table local-token-bias.json` 应用。

安装 `tokens` 可选依赖并不保证编码文件已经缓存。首次加载某些 tiktoken 编码需要访问 `openaipublic.blob.core.windows.net`；网络限制环境应通过支持的环境设置放行该域名，不能以关闭 TLS 验证或绕过网络策略解决。离线诊断无需加载 tokenizer。

## 本地模型与托管 API

| 场景 | 可用机制 | 限制 |
|---|---|---|
| 支持 logits processor 的本地模型 | 动态短语偏置、经过校验的 token 偏好 | 需要模型资源和准确 tokenizer；质量仍需实测 |
| 兼容 OpenAI 的聊天接口 | 默认使用写作指令 | 无法访问其内部生成过程 |
| 明确支持静态 `logit_bias` 的托管模型 | 服务商支持的 token 偏置 | 不是上下文短语规则，必须确认 tokenizer 与模型能力 |
| Agent Skill | 调用分析、改写与复测工具 | 不能通过自然语言指令获得 API 未开放的 logits 权限 |

短语计划不能通过“把所有 token 的权重摊开”无损转换为静态 API 偏置。PlainVoice 不应隐藏这种能力差异。

## 内容保留与错误处理

改写前后执行确定性检查，重点保护数字、URL、引文、代码，以及部分明显的否定和限定变化。失败时返回错误，不把候选改写当作合格结果。

这类检查只能覆盖有限的不变量。例如，人名替换、因果方向变化、暗含的立场变化或没有数字的事实错误，仍然需要人工审阅。为了通过检查而把数字改为文字，也不代表事实保留得更好。

工作台仅允许绑定回环接口，生成后端从运行环境配置。浏览器请求不能临时指定任意后端地址；服务不会把密钥返回给浏览器。当前工作台面向本机使用。
